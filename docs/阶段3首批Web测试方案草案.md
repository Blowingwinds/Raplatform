# 阶段 3 首批 Web 测试方案草案

> 状态：待项目负责人修改并确认。本文定义首批测试边界，不代表已获得目标授权，也不触发扫描。
> 时间均为 Asia/Shanghai。尖括号内的值在执行前必须替换；未填写的目标或能力不进入执行范围。

| 项目 | 建议填写值 |
|---|---|
| 项目名称 | `<公司 Web 系统安全测试项目>` |
| 授权记录 | `<工单或书面授权编号>`；对应 `Scope.authorization_ref` |
| 首个入口 URL | `https://<portal>.<company-domain>/`；保留协议、端口和路径 |

| 负责人和应急联系人 | `<业务负责人>`、`<安全负责人>`、`<值班联系人及联系方式>` |

默认只向首批执行目标发送请求。自动发现的子域名先作为 `subdomain.discovered` Fact 保存，补充确认后才可执行扫描。第三方 CDN、支付/身份服务、跨域跳转目标及共享云 IP 只记录关联，不自动纳入范围。DNS 解析到的 IP 也需要确认归属，不能因域名在范围内就直接扫描整个 IP。

## 2. 运行窗口与负载

| 项目 | 首版建议值 |
|---|---|
| 首轮窗口 | 2026-11-24 20:00-22:00；实际日期由业务负责人修改确认 |
| 预检查 | 19:30 前确认授权、目标、监控基线、测试账号和回滚联系人 |
| 并发与速率 | 每目标最多 2 个并发请求，平均不超过 1 请求/秒 |
| 请求预算 | 每目标每轮最多 1,000 个请求；WAF 策略变体计入同一预算 |
| 单项超时 | 单次 HTTP 请求 15 秒；单项能力 10 分钟；整轮到点停止 |
| 暂停条件 | 业务负责人要求停止、目标越界、异常写入、连续 5xx 增多、响应延迟明显恶化或出现未预期副作用 |
| 结束动作 | 停止任务、检查测试产物、保存 Evidence 与审计、通知负责人 |

首轮按“发现 -> 候选验证 -> 人工复核”顺序运行。速率和预算是保守起点，业务方可按系统容量调整；Agent 不得自行放宽。

## 3. 首批 Web 风险优先级

| 优先级 | 风险类别 | 首轮验证边界 |
|---|---|---|
| P0 | 认证与授权缺陷，包括越权和对象访问控制 | 使用两个普通测试账号对比访问结果；不读取或修改真实用户数据 |
| P0 | 文件上传、路径处理与敏感文件暴露 | 先验证类型、路径和访问控制；可执行文件上传或 WebShell 验证单列高风险动作 |
| P0 | 输入注入，包括 SQL/命令/模板等候选 | 先使用低影响探测确认候选；RCE 验证单列高风险动作 |
| P1 | 服务端请求、重定向与外部资源访问 | 只使用项目控制的回连/观察端点，避免访问云元数据或第三方服务 |
| P1 | XSS、配置错误与公开接口暴露 | 使用测试数据验证，不影响其他用户会话 |
| 横向能力 | WAF 拦截与绕过策略变体 | 仅针对已确认的候选和目标尝试受控变体；记录每次请求、响应和拦截结果，不将绕过本身视为漏洞成立 |

首轮优先完成 P0 的“认证/授权”和“文件上传/路径处理”两类候选发现，再选一项在靶场受控验证。其余类别按窗口和请求预算推进。各能力需声明风险等级、目标、预期输出、停止条件和副作用。

## 4. 测试账号与凭据引用

| 用途 | 建议引用 | 权限 |
|---|---|---|
| 普通账号 A | `env://RAPLATFORM_WEB_USER_A_USERNAME`、`env://RAPLATFORM_WEB_USER_A_PASSWORD` | 独立测试数据集 |
| 普通账号 B | `env://RAPLATFORM_WEB_USER_B_USERNAME`、`env://RAPLATFORM_WEB_USER_B_PASSWORD` | 与 A 相同权限，用于越权对照 |
| 管理账号 | 暂不启用；确需测试时单列授权和 `env://` 引用 | 最小必要权限 |
| 短期会话 | `env://RAPLATFORM_WEB_SESSION_TOKEN`；仅在系统无法使用测试账号登录时 | 限定目标和有效期 |

`env://` 是拟定的运行时凭据引用格式，阶段 3 实现时由受控执行进程读取环境变量，配置文件和任务契约只保存变量名。不要把真实密码、Cookie、Token 写入本文、Git、Fact 或审计记录。公司系统的敏感原始 Evidence 需加密保存，面向黑板和报告的内容先脱敏。若加密和脱敏能力尚未完成，公司系统首轮只能执行无需凭据的检查。

## 5. 高风险动作清单

默认不在公司系统执行 RCE、WebShell 上传、实际数据修改或破坏性验证。确需纳入首轮时，由负责人逐项填写目标、能力、验证方法、最大请求数、预期副作用、清理步骤和批准记录；Gateway 在调用前核对批准、Scope、Lease 和预算。靶场可先用于验证这些能力及停止流程。

| 动作 | 首版状态 | 公司目标与批准记录 |
|---|---|---|
| RCE 最小化证明 | 靶场验收；公司系统待逐项确认 | `<目标 / 工单 / 批准人>` |
| WebShell 上传及利用验证 | 靶场验收；公司系统待逐项确认 | `<目标 / 工单 / 批准人 / 清理步骤>` |
| WAF 策略变体测试 | 在已确认目标和请求预算内执行 | `<目标 / 允许的能力 / 窗口>` |

## 6. 首轮验收

1. 每个实际请求都能关联项目、Scope、Task、Agent、Session 和审计事件；越界请求被拒绝。
2. 资产、服务、Web endpoint、漏洞候选和验证结果写入黑板，能从 Fact 回查 Evidence。
3. 靶场覆盖至少两类 Web 风险候选、一项受控验证和一次 WAF 策略变体测试。
4. 公司授权目标完成实际扫描及一项非破坏性验证，并由业务负责人确认无未预期影响。
5. 输出精简报告，区分“候选”“已验证”“无法验证”，记录范围、时间、请求量、证据和清理结果。

## 7. 负责人需要修改的内容

- 填写真实入口 URL、明确的 FQDN/端口/路径及排除项，并确认发现子域名的纳入流程。
- 确认窗口、业务监控与应急联系人；按系统容量调整速率和请求预算。
- 确认首批 P0/P1 风险顺序、两个测试账号及凭据提供方式。
- 对公司系统的 RCE/WebShell 验证作出逐目标决定；未填写时保持待执行状态。
