## 当前架构决定

### 决定 1：平台负责治理，Agent 负责具体能力

Agent 自己实现其工具调用和领域逻辑；平台负责任务契约、能力匹配、授权范围、MCP 调用、租约、审计和结果归一化。

### 决定 2：黑板保存规范化事实，证据保存原始结果

黑板面向编排和协同，Evidence 面向审计和复核。二者通过 `evidence_ref`、`session_id` 和 `task_id` 关联。

### 决定 3：先 Mock，后真实 Agent

第一版先通过 Mock Planner、Mock MCP Transport 和 Mock Agent 验证数据流与状态机。真实云端模型和真实 Agent 只替换适配器，不改变核心契约。

### 决定 4：第一条演示链路包含受控漏洞验证

首个闭环覆盖目标规范化、子域名发现、资产、端口、服务、网络关系、漏洞候选和靶场中的受控验证证据；不扩展到后渗透、持久化或权限维持。

### 决定 5：跨会话协作规则

每个阶段任务 Agent 在修改代码前必须先与用户讨论并提问，说明它会如何开发、本阶段有哪些设计问题需要敲定。未获得用户确认时只做只读分析和方案整理。

### 决定 6：Demo 优先

最高优先级是大约一周内交付能在靶场测试高危漏洞发现、RCE 或 shell 上传受控验证并输出精简报告的 Demo。生产级分布式、完整 ATT&CK 和复杂产品化能力后置。

### 决定 7：事实身份、版本和冲突

平台按项目、事实类型、目标及该类型关键字段生成稳定 Fact ID。事实当前状态与历史观察分开保存；同一事实更新版本并产生增量事件。不同 Agent 在 10 分钟内给出相反的 active/invalidated 观察时，当前事实标记 conflicted，不覆盖先前结论；下一次复测可解除冲突，双方原始观察始终保留。

### 决定 8：Agent 结果和 Evidence 契约

Agent 负责把 Python 脚本或 Nmap 输出解析为结构化 `observations`；平台把每次 Agent 结果及原始工具输出保存为一份 Evidence，再将观察归一化为 Fact。一个 Evidence 可被多条 Fact 引用，一条 Fact 可回查多次 Evidence。自定义事实类型必须提供 `identity` 字段。

### 决定 9：靶场测试凭证明文

阶段 2 的 `credential.validated` Fact 可以明文保存受控靶场的测试凭证值，Evidence 也保留原始结果。这是 Demo 专用决定；接入真实凭证前必须另行设计保密存储、访问控制和展示规则。

### 决定 10：阶段 3 接入真实扫描与 Web 验证

阶段 3 不再只验收 Mock MCP 调用，还要接入真实扫描和专用 Web 漏洞探测/利用 Agent，覆盖常见风险类别及受控 WAF 拦截策略变体。平台仍负责授权范围、风险、批准、Lease、请求预算和审计；Agent 负责具体工具和验证逻辑。高风险的 RCE 或 shell 上传验证须按目标和能力单独批准，执行最小化证明并清理产物。阶段 3 在靶场验证能力，并在单独确认范围、动作和运行窗口的公司系统上验收实际扫描与非破坏性验证。公司系统的敏感原始 Evidence 需加密保存，Fact 与审计记录只保留引用和脱敏摘要，真实凭据和会话密钥不得明文落库。

- 当前已具备黑板业务服务；真实信息搜集脚本、Nmap Agent、MCP Gateway 和编排功能尚未实现。
- 当前没有锁定依赖版本或发布安装包配置。
- 当前架构图是设计产物，不代表功能已经实现。
- 云端模型、真实 MCP 服务和真实渗透 Agent 尚未接入。
- 常见 Web 风险类别和 WAF 拦截策略变体目前只是阶段 3 范围，尚无真实检测或验证实现；公司系统实测目标、运行窗口、测试账号和允许的高风险动作尚未指定。
- 当前未建立生产级身份认证、密钥管理、多租户隔离和分布式一致性。
- 黑板当前使用 SQLite JSON 载荷和单进程连接；增量查询会扫描该项目事件，尚未实现生产级并发或索引优化。
- 冲突判定使用 10 分钟观察窗口；当前由后续复测解除冲突，人工裁决接口尚未实现。
- 受控靶场测试凭证明文写入 Fact 与 Evidence；不得将此存储策略直接用于真实凭证。
