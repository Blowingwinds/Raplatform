## 当前架构决定

### 决定 11：蜂群模型 + CrewAI Hierarchical

采用蜂群模型：信息搜集 Agent（工蜂群1）收集信息填充黑板 → 蜂后（CrewAI Manager）读黑板决策 → 派遣漏洞探测 Agent（工蜂群2）或漏洞利用 Agent（工蜂群3）→ 结果写回黑板 → 蜂后再次决策。

技术实现：CrewAI Process.hierarchical + 我们的安全层（Gateway/PolicyGuard/Blackboard）

### 决定 12：多专业 Agent 体系

3 个漏洞探测 Agent 各有所长：
- framework_vuln — 框架/Runtime CVE（Spring/Django/Laravel/Apache/Nginx...）
- web_attack — 通用 Web 攻击（SQLi/XSS/SSRF/文件上传/CORS...）
- component_vuln — 组件/插件/服务漏洞（WordPress 插件/npm/Redis/MongoDB...）

Agent 自主推理渗透测试路线，nuclei/sqlmap 作为执行工具而非决策者。

### 决定 13：Agent 自主推理

Agent 根据指纹和拓扑自主规划渗透路线，nuclei 从 `-tags`（广撒网）变为 `-id`（精准打击）。Python CLI（execute_python）让 Agent 自主写测试脚本。

### 决定 14：不引入完整框架，借 CrewAI 做协调层

CrewAI 负责 Agent 定义、任务分发、并行调度、结果收集。我们的 Gateway/PolicyGuard/Blackboard 作为安全层包裹在底层。CrewAI Agent 的 tool 调用经过我们的安全门禁。

### 决定 15：CLI 优先，无 LLM 可运行

系统入口采用 CLI（`python -m src scan|status|report`），默认使用 FakeCrewRunner + InProcessTransport 不依赖 LLM。FakeCrewRunner 从 Task.description 正则提取 `tool_name(k=v)` 模式直接调用工具函数，走完整 Gateway 安全链。生产环境可替换为 RealCrewRunner + 真实 LLM。

### 决定 16：跳过加密/脱敏，直通靶场

当前阶段仅为测试环境和靶场，不涉及生产数据。Evidence 加密和 Fact 脱敏留到生产环境接入前实现。
